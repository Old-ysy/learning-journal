3 分钟演示提纲

第一段 · 用户问题（约 30 秒）

一句话
我每天想坚持几个小习惯，但手机上记的东西一换设备就没了。我希望打开一个网址就能看到自己坚持了几天——而且数据存在云上，不是存在这台浏览器里。
三个痛点
① 数据跟着浏览器走，换设备就丢 → ✅ 存 CloudBase PG，公网可访问
② 不知道坚持了多少天 → ✅ 连续天数由打卡记录实时算出
③ 想给别人看一眼 → ✅ 有公网链接，粘贴即可打开
演示动作
打开首页，指着列表念一条：「跑步 30 分钟，已连续 3 天」。

第二段 · 核心流程（约 60 秒）

① 静态托管 the-old-...tcloudbaseapp.com │ 浏览器打开，拿到 index.html / app.js / style.css ▼ ② 前端 app.js │ USE_CLOUD 判定 → fetchHabits() │ 跨域请求（网关按安全域名白名单回显 ACAO，放行） ▼ ③ 云函数 habits（四层） index.js 只做 HTTP 方法分流 handlers 编排：读参数 → 调 repo → 决定错误码 repo 唯一写 SQL 的地方 lib 数据库连接与工具 ▼ ④ PostgreSQL habits 表 + records 表 7 个习惯、20 条打卡记录
设计点一句话说明
分层SQL 只在 repo/habits.js；「查不到算 404」是 handler 的判断，repo 只回答「查到几条」
防重复函数预检 + 数据库唯一索引两层。只做预检的话，并发下两个请求会同时通过检查
数据源切换location.protocol === 'https:' 决定走云端还是 localStorage，本地打开不会误调线上
