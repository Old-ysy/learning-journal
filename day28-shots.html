如实记录 · 三个发现（验收就是要报忧）：
  • 网关对 GET 有短时缓存：写入后立刻不带参数 GET，可能读到几秒前的旧数据，几十秒内自动更新。响应头本身是 no-store，是网关层行为，函数侧改不了。缓解：前端本就整页刷新后重新拉取，实际影响窗口很小。
  • 冷启动偶发：当天第一笔 POST 返回 ok 但数据未落库（1 次），随后连续 4 轮回环无法复现。已如实记录，不在验收上藏。
  • 页面端是「只读接线」边界（Day 20 范围）：页面上的新增/打卡/删除只写 localStorage，云端写入能力完整在 API 层（今天 ④ 验证）。这是全项目最大的如实标注项。

200 字结营总结

28 天做完一个习惯打卡小工具：从 PRD 到原生 JS 页面，再到云函数 + PostgreSQL，最后发布上线。最大的收获不是代码，是验收方式——写完不等于做完，能跑不等于跑对：Day 26 发现线上一直跑旧代码，从此发布前必跑 preflight 脚本核对 md5；Day 27 冷启动走查抓到 5 个卡点，才明白自己以为的顺手和真实用户的顺手是两回事。项目的边界也如实记录在案：页面端仍是只读接线，云端写能力完整在 API 层。作品在线，数据在库，方法在手上。

今日一问：28 天里最大的一个认知改变？

以前以为做东西的难点是「把功能写出来」，这 28 天发现难点是「知道自己写出来的东西对不对」。页面能打开、接口有返回、命令没报错——全都不算数。要哈希对哈希、写完读回、让真实用户亲手点一遍。信任不能建立在「它说成功了」上面，只能建立在可核对的证据上面。
