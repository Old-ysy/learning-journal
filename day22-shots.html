结论：DELETE 生效。详情查询 NOT_FOUND、列表里没有该 id、条数回到 7。 另用 SQL 复核：SELECT COUNT(*) FROM records WHERE habit_id='h_muz10cjd84g9' → 0（记录一并清干净，无残留）。

⑤ 删除的防误删设计（缺 id 会被拒绝）

场景响应
不带 id 直接删BAD_REQUEST「删除必须指定 id，不支持批量删除」（一行没删）
id 不存在NOT_FOUND「习惯不存在：h_not_exist_zzz」（不静默，明确告知）
三道确认：① 前端 window.confirm 弹窗（app.js:623）→ ② 服务端缺 id 直接拒绝，没有「删全部」的入口 → ③ 服务端先读到才删，读不到就 NOT_FOUND，绝不做「删了但不知道删没删成」。
