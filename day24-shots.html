③ 顺着调用链找谁该负责

app.js:758  bootstrap();                  ← 顶层调用
app.js:692    else loadWithState();
app.js:752      load();                     ← 三层里一个 try/catch 都没有
app.js:122        JSON.parse(raw);          ← 抛错点

看 load() 自己的注释：「让上层决定显示 error 状态」 —— 意图写得明明白白， 但上三层一个都没接。所以：

  • 异常无人接管 → 变成 Uncaught
  • bootstrap() 从 752 行中断 → 后面的 render() / applyRoute() 不执行
  • 结果就是截图 1 那片空白

④ 差点误判的一次（值得记下来）

第一次复现时看到页面显示「还没有习惯，从第一个开始吧」，差点当成「数据静默丢失」的 Bug。
查下去才发现：测试工具的每次 open 都是全新浏览器上下文，localStorage 根本不跨会话， 写进去的脏数据在下次打开时早没了 —— 那是测试假象。
改成「在同一次页面存活期内完成注入 + 重载」才拿到真结果。
教训：复现失败要先怀疑复现方法本身，别急着改代码。

余力加练｜第二个 Bug：写盘也没人兜底

和主任务同一个疏漏家族
主任务修的是「读坏了怎么办」。顺着同一条思路往回看，写那一层同样裸着： save() 里只有一句 localStorage.setItem(...)，没有 try/catch； 而 addHabit / toggleHabit / deleteHabit 三个调用点全是 save(); render(); 连着写 —— save 一抛，render() 就跟着不执行了。

① 怎么复现的

真实世界 setItem 被拒很常见：Safari 隐私模式禁用 Storage、配额写满、 站点策略把 Storage 划进黑名单 —— 抛的都是这一句的 DOMException。 在页面 JS 之前注入一句「写必失败」来模拟配额超限：

Storage.prototype.setItem = function () {
  throw new DOMException(
    "Failed to execute 'setItem' on 'Storage': Setting the value of 'habits' exceeded the quota.",
    'QuotaExceededError'
  );
};

② 修复前：点了完全没反应

Console ▾ 1 error
Uncaught QuotaExceededError: Failed to execute 'setItem' on 'Storage': Setting the value of 'habits' exceeded the quota. @ app.js:136
点了「添加」之后修复前修复后
列表0 项，纹丝不动1 项，正常出现
提示空，一句都没有「已添加，但没能保存到本地（刷新会丢失）」
输入框「晨跑」还留在框里正常清空
控制台Uncaught（未捕获）只是 console.error
最狠的是这个：第一条其实已经进了内存，但界面毫无动静。用户会以为没点上、再点一次 —— 于是越点越多，刷新之后一条都不剩。

③ 修复：不回滚，但把风险说清楚

function save() {
  try {
    localStorage.setItem(STORAGE_KEY, JSON.stringify({ habits: state.habits }));
    storageWritable = true;
    return true;
  } catch (err) {
    console.error('写入本地数据失败：', err);   // 原文只进控制台
    storageWritable = false;                    // 界面上给人话
    return false;
  }
}
  • 写失败不回滚：数据已经在内存里了，先让人看得见
  • 失败状态不塞进返回值：addHabit / toggleHabit 的返回对象是 Day 11 回归测试的断言目标，加字段会连带让旧断言失效 —— 改用模块级标记传递
  • 三条路径各给一句人话：添加 / 打卡 / 删除

⑤ 中途被自己坑了一次

改完重跑，结果跟没修复一模一样。查了三轮才抓到：文件里有两个同名 save() （编辑时旧的那个没删干净），JS 里后声明覆盖先声明，所以一直跑的是旧版。
而 node --check 一声不响 —— 重复函数声明在语法上完全合法。
教训：改完要确认跑的到底是哪份代码，别信「文件我改过了」。
