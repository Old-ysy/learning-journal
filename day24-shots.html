③ 点「重试」能真的走出去

点「重试」→ 弹确认框：本地数据已损坏，无法正常读取。要清空损坏的数据并重新开始吗？
                        （原来的记录将无法找回）
点「确定」→ 坏数据已清除 ✅   错误卡片消失 ✅   回到空列表正常使用 ✅
为什么要有这一步：坏数据还躺在 localStorage 里，光重试每次都会再抛同一个错， 永远出不来。删数据要用户点头，不自作主张。

② 换方向：不打输入，打「启动时读到的东西」

既然输入层干净，就把怀疑放到持久化层 —— 页面启动时从 localStorage 读回来的那段数据。 把三种坏数据形态灌进去：

脏数据形态结果
JSON 写了一半被截断炸，Uncaught SyntaxError
合法 JSON 但 habits 不是数组不炸（有 Array.isArray 兜着）

只有第一种炸 —— 说明问题在「解析失败」这条路径，不在「结构不对」。范围进一步收窄。

③ 顺着调用链找谁该负责

app.js:758  bootstrap();                  ← 顶层调用
app.js:692    else loadWithState();
app.js:752      load();                     ← 三层里一个 try/catch 都没有
app.js:122        JSON.parse(raw);          ← 抛错点

看 load() 自己的注释：「让上层决定显示 error 状态」 —— 意图写得明明白白， 但上三层一个都没接。所以：

  • 异常无人接管 → 变成 Uncaught
  • bootstrap() 从 752 行中断 → 后面的 render() / applyRoute() 不执行
  • 结果就是截图 1 那片空白

④ 差点误判的一次（值得记下来）

第一次复现时看到页面显示「还没有习惯，从第一个开始吧」，差点当成「数据静默丢失」的 Bug。
查下去才发现：测试工具的每次 open 都是全新浏览器上下文，localStorage 根本不跨会话， 写进去的脏数据在下次打开时早没了 —— 那是测试假象。
改成「在同一次页面存活期内完成注入 + 重载」才拿到真结果。
教训：复现失败要先怀疑复现方法本身，别急着改代码。
